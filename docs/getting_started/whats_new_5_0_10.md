# 5.0.10 更新说明

> 写给付费客户的人话版。没在真实 Telegram 里验证过的地方，下面都写明了。

## 新功能
- **入群遇到「网页验证」（Cloudflare 人机验证 / 小程序验证）也能自动过了**：进群后机器人让你点「完成验证」打开网页时，软件会在桌面自己开一个无痕浏览器窗口打开验证页，页面自己通过后窗口自动关闭，并**等账号在群里真的能发言了才算通过**（页面打开了不等于通过）。需要电脑里装有 Chrome 或 Edge、人在电脑前（会弹出一个窗口，请不要手动去点）。群发、养号退群重进、补群、群漏斗的「进群」都走这套；Agent（MCP）也可以用 `tg_solve_captcha` 的 `web_url` 参数复用。只在一个测试群里实测通过过，其它验证机器人请先小批量试。
- **封禁 / 冻结 / 双向受限（红灯）的账号可以一键放行去做事了**：账号页「⋯ 更多 → 放行红灯号」，勾选要放开的——「进群 / 进频道」（加群后做关键词监控，不发消息）、「群内发言」，选有效期（最长 30 天），随时可以「撤销已放行」。软件只是不再拦截，**账号本身的限制还在，Telegram 放不放行不由软件决定**（实测：红灯号可以加群；有的号在群里发言仍会被 Telegram 拒绝）。Agent（MCP）可以用 `grant_red_access` / `revoke_red_access`，支持一次放行多个号或「所有红灯号」。
- **代理（渠道合伙人）的下载归属和 OEM 贴牌**：从代理落地页下载的 Windows 安装版 / 便携版，装好首次联网时设备自动归属到这个代理，软件名 / 徽标等品牌信息随后自动换成该代理的（窗口标题几秒内更新，重启后完全生效）。macOS / Linux 暂没有这个标记。
- **发出去的消息被机器人立刻删掉时，Agent 能看到原因了**：有些群要求先关注频道才能发言，否则消息发出去就被删。`tg_send_message` 现在会等几秒再回读，发现消息没了就读出机器人的提示、要关注的频道和「我已关注」按钮，Agent 据此加频道、点按钮后重发（软件不会替账号自己去加频道）。这一块没在真实 Telegram 里验证过。

## 改进
- **申诉的人机验证**：每个验证页各开一个独立的无痕窗口，互不影响；「同时验证」数量可以调（1 = 按队列一个一个来），上限定为 3（实测同时开 5 个只有 3 个有反应）。验证浏览器会通过系统注册表找 Chrome / Edge，装在非默认目录也能找到。
- **账号检测 / 导入不会再无限卡住**：授权探测、读取账号信息、SpamBot 检测、断开连接、等 Session 锁都加了硬超时，卡住时返回明确的「超时」原因，不再一直转圈。
- **养号第一阶段**：24 小时内允许在群里发 2 条（原来是 0），其余额度不变。
- **入群验证机器人的私聊不再被风控额度拦住**：新买的号常带双向受限，以前 `/start` 被当成「私信」、额度为 0，过不了闸，几分钟后被机器人踢出。现在验证流程里发给那个验证机器人的 `/start` 单独放行（限时、限条数、落审计）。
- **自动回复不占私信额度**；账号中枢新增「今日私信」列；支持批量修改用户名。
- **入群验证返回更完整**：Agent 能拿到验证类型、机器人回复原文与按钮、验证剩余时间、账号在群里的发言权限和前置条件；验证通过只表示「群里放行了」，账号层面被 Telegram 限制时仍可能发不出消息，说明里写得很清楚。
- 剧本回放发言前先标记已读；代理绑定不可用时拒绝连接（不再悄悄直连）；连接加了超时。

## 注意
- 上面带「实测」的结论都只在我们自己的测试群里验证过一次；真实环境里请先用小号小批量试。
- 红灯号放行后，**加群后做关键词监控没有在真机跑过**（读代码看引擎没有按账号状态过滤）；命中后要转发消息的话还需要同时放行「群内发言」。
- 同一批账号不要在两台电脑里同时登录：同一个 session 在两处同时使用会被 Telegram 作废。

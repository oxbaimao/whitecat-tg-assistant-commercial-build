# 5.0.16 更新说明

> 写给付费客户的人话版。没在真实环境验证过的地方，下面都写明了。
> **发布平台以实际发布为准；本说明对应的改动目前只做过模拟测试。**

## 改进：账号限制检测不再依赖语言
- 以前：@SpamBot 用非英文（西语、葡语、俄语、印尼语、阿拉伯语、波斯语、土耳其语、印地语、中文等）回复时，软件可能认不出是「正常」还是「受限」。
- 现在：按多语言词表和「限制到某日期」的结构来判断。**认不出的回复一律记为「未核实」**，不会猜成正常，也不会覆盖账号已有的状态；返回里会附上打码后的原文，方便你判断。

## 改进：卖家号「安全接管」更稳、更透明
- 接管前先由卖家的老会话把账号上其他设备 / 会话登出（不受「新会话 24 小时内不能踢人」的限制）。可以用保留名单 `keep_session_hashes` 留下你自己的设备；`pre_clear_others=false` 可关闭这一步。
- 新增只读动作 `inspect`：先连接卖家会话看一眼账号当前登录了哪些设备，用完立刻断开，帮你决定保留哪些。
- 预览里会提醒：包裹里的两步验证密码是静态值，可能已被改过，请确认后用 `two_fa` 显式传入。
- 步骤清单和「部分完成」的措辞更如实：除保留名单外只剩新会话才算完成，否则标为部分完成并说明原因。
- 发起自有登录前先做线路预检，连接失败会重试。
- 软件界面新增接管面板（「安全与转换」页第 6 个标签），与 MCP 工具共用同一个引擎，规则一致。
- 接管面板可以直接「从账号池选择」已导入的号（在线的号会提示先断开，因为同一把密钥不能同时有两个客户端）；整个面板改为可滚动，窗口矮时不再互相挤压重叠；「批量建群建频道」页左栏加宽，大字体 / 高缩放下不再被右侧裁掉。
- **批量接管**（「安全与转换」页第 7 个标签）：选一个文件夹自动扫描里面所有 session 文件 / tdata 号包（也可一键加入账号池里的离线号），勾选后设置同时接管的号数（线程 1–5，建议 1–3）一次接管很多个号；每个号单独显示状态，可随时停止。批量模式不逐号保留设备（每个号除新会话外的设备都会被登出）；需要保留接码客户端的号，请用单个接管。
- 接管开始和结束（完成 / 需要验证码 / 部分完成 / 中止 / 失败）都会弹窗提醒，不用下拉去看日志。
- 修复：接管完成后新会话因为账号库里已有同号旧文件而没能放入——现在旧文件会留底（接管目录的 replaced_pool 下），再放入新会话；新增「补入账号库」按钮，对已经入库的号会明确告诉你「早已完成」，不再显示成错误。
- 修复（重要）：旧版在同一个号上再点一次「开始接管」时，会把上一轮换出的新会话文件删掉。现在新会话文件只会移走留底、不会删除；上一轮已经换出新会话的号，再点开始会被直接拒绝并提示该怎么做。
- 接管支持号商常见布局：选外层文件夹会自动找到里面的「手机号/tdata」，并读取 tdata 旁边的 2FA.txt。
- 请求登录验证码失败时，错误信息会带上出错的代码位置，方便定位（上个测试版里有人遇到 `bytes or str expected, not int`，我们本机复现不出，根因未确认，这一版先补了诊断）。

## 注意（如实）
- 以上**都没有在真实 Telegram 里验证过**，只有模拟测试：多语言词表对真实 @SpamBot 各语言回复的覆盖、接管流程（验证码投递、清理其他会话、2FA 设置）、新界面面板的实际操作。
- 接管是不可逆操作（卖家的共享密钥会被作废，其他设备会被登出）。真实使用前请先用 `plan` / `inspect` 看清楚。

# 5.0.13 更新说明

> 写给付费客户的人话版。没在真实环境验证过的地方，下面都写明了。
> **本版目前只发布 Linux；Windows / macOS 暂未随本版发布。**

## 通过 MCP / `--serve-mcp` 新导入的账号，终于按你绑定的代理走了
- 以前：在 Agent 里先给账号绑了专属代理，再用 `import_session` 导入，实际连接却仍走「智能线路」，卡 60 秒后只说「超时」，也看不出卡在哪。现在：导入会按账号手机号找到你绑定的专属代理（没有绑定才回落到智能线路），返回里会写明**实际走的线路**；绑定也会立即对运行中的服务生效，不用重启。
- 连接失败时，返回里会带上**失败发生在哪一段**（连不上代理 / 代理通了但到不了 Telegram / 隧道通了但握手没完成）和**底层错误原文**，不再只有一句「超时」。智能线路在新建连接前会先自检，不通就直接报错，不再干等。
- `tg_manage_proxies bind` 现在号码带不带 `+` 都行；任何一个号码对不上账号会明确报错，不会再「成功绑定 0 个」。

## 新增：卖家号「安全接管」（`tg_takeover_account`，MCP 共 58 项）
- 买来的 session / tdata 与卖家共享同一把登录密钥，卖家手里留有副本。本工具把卖家密钥当成**一次性的接码桥**：连接卖家会话 → 对同一手机号发起软件自己的登录并自动取验证码 → 确认新会话是同一个账号 → 作废卖家密钥并回读设备列表（必须只剩 1 条）→ 给新会话设置两步验证并放进账号库。
- 安全设计：新会话没验明之前，绝不会对卖家会话做任何注销；账号有两步验证而密码缺失 / 不对时会干净中止，卖家密钥原样保留；验证码、2FA、密钥不会出现在日志或返回里；接管期间账号处于隔离状态，不参与任何业务动作。
- **默认只预览**；真实执行需要写入权限，并且要明确确认（会让账号收到验证码、不可撤销地作废卖家的密钥、设置 / 更换两步验证）。

## 注意（如实）
- 以上**都没有在真实的 Telegram / 真实的 Muse 虚拟机里验证过**，只做了模拟测试。尤其是接管流程：Telegram 对刚登录的新会话可能暂时不允许它终止其他会话，遇到时接管会停在「未完成」并告诉你什么时候可以继续，不会假装成功。
- 接管暂时只有 MCP 入口，没有界面按钮，也不支持一次接管多个账号。
